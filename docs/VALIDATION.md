## Browser and visual scope

The privacy probes check initial online delivery and generation without further network requests, storage writes, weak randomness, history state or service-worker use. Opening a standalone file produces zero network requests. Copy is explicit and exact, denial has manual-copy guidance, and late clipboard callbacks cannot restore cleared state. Settings changes, hidden-tab/page lifecycle and simulated five-minute expiry clear the DOM. Missing RNG/digest, failed integrity, insecure context and embedding leave generation locked, including synthetic dispatch of a click on the disabled button. Without JavaScript, the explanation remains readable and generation stays disabled.

CSP tests deny a synthetic arbitrary script, connection and form submission, and a real foreign ancestor is blocked. Gecko's denied frame has no execution context, so its native ancestor-policy rejection is the observed result rather than an invalid attempt to query that frame. Chromium/WebKit observe absence of generator content. This engine difference is documented, not used to skip the test.

Each engine checks 48 locale/theme/viewport combinations at widths 320, 360, 390, 419, 420, 421, 759, 760, 761, 768, 1024 and 1440 pixels. Native controls, initial/open disclosures, exact inventory, reduced motion, keyboard operation, 200 percent text and 20-word results are exercised. The checked inventory is seven radios, six checkboxes, two ranges and seven disclosures. No select/search/progress/meter is present, so those geometry probes are NOT_APPLICABLE.

Synthetic screenshots were generated and opened for desktop, mobile, minimum width, footers, long results and forced colors. The high-contrast light surface now uses the original primary logo even with a dark theme. The unchanged shared filename-based header probe reports its documented data-URL limitation. Exact decoded SVG bytes and all remaining geometry/chrome probes compensate as described in DECISIONS.md. That unsupported probe is not silently represented as a clean standard-inspector PASS.

Axe's WCAG 2 A/AA and WCAG 2.1 AA scan found zero violations in the light long-result/text-zoom fixture and the dark experimental-profile/low-space-warning fixture on all three engines. Opening a dark screenshot caught a low-contrast experimental note that the initial light-only axe fixture had not covered. The note now pairs neutral surface and text tokens, while retaining its orange border. This is not manual screen-reader validation. Playwright WebKit is an engine test, not a claim about every shipping Safari/iPhone combination.

## Measured performance

Lighthouse 13.5.0 used Chromium 153.0.8010.12 on an AMD Ryzen 5 PRO 7530U, 12 logical CPUs and approximately 15.9 GB RAM. Three cold runs per mode used Lighthouse's simulated mobile/desktop settings, retained in each raw report. Mobile simulation uses 4x CPU slowdown, 150 ms RTT and 1,638.4 Kbps throughput. This is localhost lab evidence, not a phone trial, field INP or CrUX sample.

| Final cold runs | Performance score | LCP                                | TBT                        | CLS          |
| --------------- | ----------------- | ---------------------------------- | -------------------------- | ------------ |
| Mobile          | 96 in all three   | Median 2,187 ms, range 2,184–2,195 | Median 84 ms, range 5.5–86 | About 0.0003 |
| Desktop         | 100 in all three  | Median 482.5 ms, range 482.5–483.5 | 0                          | About 0.0024 |

The provisional median budgets of LCP <= 2,500 ms, TBT <= 200 ms and CLS <= 0.1 pass. Accessibility and best-practices scores are 100 in all six runs, with the manual-evidence boundary preserved. SEO is 92. Its robots audit reports a `Network.loadNetworkResource` CSP violation rather than malformed content. An independent direct HTTP request returned 200 and the actual valid robots directives. `connect-src 'none'` remains intact. No score is relabeled or security restriction relaxed for Lighthouse.

The representative synchronous generation timings use 30 samples after one warm-up. The default password median is 0.2 ms, 128-character required-group password 0.6 ms, 20-word EFF 0.8 ms, accented Vietnamese 0.4 ms and ASCII Vietnamese 0.3 ms. These handler timings exclude the broader real-user event/paint path and are not INP. The EFF median was 19.5 ms before removing repeated vocabulary UTF-8 length scans. Verified maximum lengths are now computed once at startup. First observed readiness median changed from 162.5 to 170.9 ms and repeat readiness from 61.3 to 64.1 ms. Mobile Performance median changed from 97 to 96. Those startup/measurement tradeoffs are retained rather than hidden behind the interaction improvement.

An earlier run contended with browser tests is retained locally under `output/performance-baseline-contended/` but is not the controlled before/after comparison. No external telemetry or public benchmarking service received the generator or a secret.
