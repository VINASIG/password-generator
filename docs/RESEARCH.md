# Research and design assessment

Reviewed on 6 October 2026. The starting question was which properties a trustworthy static generator can establish, not which feature checklist would make it appear strongest. Product documentation is evidence of advertised behavior, not an audit of a competitor's implementation. No comparative usability or performance ranking was performed.

## Standards and estimation

[NIST SP 800-63B-4](https://pages.nist.gov/800-63-4/sp800-63b.html) addresses verifiers, not certification of generators. Single-factor verifier passwords have a 15-character minimum, while composition requirements are discouraged. It also discusses Unicode, normalization and accepting longer passwords. This project defaults to 20 ASCII characters and makes composition a site-compatibility option. A generator cannot determine a service's KDF cost, truncation behavior, rate limits or account recovery risk.

[W3C Web Cryptography](https://www.w3.org/TR/2017/REC-WebCryptoAPI-20170126/#Crypto-method-getRandomValues) defines `getRandomValues` for cryptographically strong random bytes and an operating-system-seeded generator. The specification does not provide an information-theoretic entropy lower bound for each byte. Selection proofs are conditional on the trusted browser source behaving as intended. They are not measurements of the host's physical entropy.

[zxcvbn research](https://www.usenix.org/conference/usenixsecurity16/technical-sessions/presentation/wheeler) addresses estimating guessability of human-selected passwords using patterns and dictionaries. For an unedited outcome from a known uniform generator, counting the specified space is more directly inspectable. A heuristic score would add a large dictionary dependency and an extra claim without proving Vietnamese recall or typing quality. The UI therefore shows rounded-down generation-space bits and lengths, not a strength bar or cracking clock.

The 80- and 128-bit word-count buttons are explicit mathematical examples, including compatibility with the existing Vietnamese CLI examples. They are not NIST password targets or assurance grades. Seven EFF draws exceed 90 whole bits. Seven accented Vietnamese draws exceed 80, while seven ASCII draws yield 78. The UI does not hide this change or pad it with delimiter entropy.

## Algorithm alternatives

| Approach                                                                        | Distribution                                               | Cost and audit surface                                                            | Selection                                                  |
| ------------------------------------------------------------------------------- | ---------------------------------------------------------- | --------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| Independent unbiased characters, retry the entire string until all groups occur | Uniform conditional on the policy if implemented correctly | Simple, but retries can become severe for small retained groups and short lengths | Valid baseline, rejected as the general compatibility path |
| Insert one from each required group, fill remaining positions, then shuffle     | Not generally uniform                                      | Easy to implement, difficult to justify an output-space entropy claim             | Rejected after exhaustive counterexample                   |
| Count valid completions, sample one integer rank, unrank it                     | Uniform conditional on successful random sampling          | More code, bounded four-group state space and exact independent oracles           | Implemented                                                |
| Per-character weighted sampling from completion counts                          | Uniform if each weighted draw is unbiased                  | Similar proof, repeated random draws and more RNG calls                           | Reasonable alternative, no demonstrated advantage here     |

The separately implemented enumeration in [measurements.json](research/measurements.json) exhausts a length-four alphabet with groups `ab` and `01`. The insertion/shuffle construction has 1,536 equally likely decision paths over 224 valid outputs. Some outputs have six paths, others eight. This is a reproducible counterexample to that construction, not a claim that any named competitor uses it. The rank construction maps one rank to each of the 224 outputs.

## Architecture alternatives

| Approach                                  | Advantage                                          | Material drawback                                                             | Decision                                                               |
| ----------------------------------------- | -------------------------------------------------- | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Server-side generation                    | Central operational controls                       | The server handles secrets, and transport/logging become secret paths         | Rejected for this threat model                                         |
| React/Astro or another hydrated framework | Familiar components and ecosystem                  | Runtime/hydration code without a demonstrated need for this bounded interface | Strict TypeScript and build-time HTML chosen                           |
| Separate fetched wordlists and scripts    | Smaller first document, shared cache               | More runtime requests, source switching and offline packaging paths           | Lists and assets embedded with startup integrity checks                |
| Service-worker offline cache              | Convenient repeat use                              | Update/lifetime complexity and another persistent execution surface           | Explicit immutable standalone files chosen                             |
| A dedicated desktop password manager      | Trusted storage, integration, platform protections | A different product and deployment model                                      | Recommended as the place to save results, outside this project's scope |

The selected design trades an approximately 276 KB online document and 402 KB standalone offline document with embedded legal notices, plus repeated locale payload, for no runtime dependency and no runtime request. Exact bytes are in the build record. Source remains readable and not minified. CSP hashes restrict the embedded script/style. The [CSP specification](https://www.w3.org/TR/CSP3/#directive-frame-ancestors) excludes `frame-ancestors` from meta policies, so online deployment additionally needs response headers. Offline generation separately refuses embedded contexts.

## Failure evidence and limitations

The [Trust Wallet Core advisory CVE-2023-31290](https://github.com/advisories/GHSA-pm4f-pggw-8jwc) describes inadequate entropy in a browser-extension wallet path, including exploitation. It supports researching protocol key generation separately, not adding wallet/SSH/key exports to a password UI. Wallet seeds, nonces and protocol keys are deliberately outside version 0.1.

[KeePass 2.54 release notes](https://keepass.info/news/n230603_2.54.html) describe improved process-memory protection of secure edit controls and clipboard behavior. A mask and a Clear button are not a guarantee of physical memory erasure. This application clears DOM values and references, but JavaScript strings, BigInts, clipboard managers, swap, extensions and screenshots remain outside an erasure claim.

The development dependency trial found [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm), an unpatched stack-exhaustion issue in `braces` propagated through Stylelint's dependency graph. The replacement and compensating checks are recorded in [DECISIONS.md](DECISIONS.md). This is a development supply-chain decision, not evidence of a secret leak in a shipped generator.

Automated research can still examine distributions, malformed Unicode, encoding collisions, adversarial settings, CSP/lifecycle behavior, build drift, protocol-independent interoperability and performance. It cannot establish delayed recall, regional familiarity, acceptability, input effort, typing error rates or user preference. Those require actual participants or external linguistic review. No proxy score is substituted for missing human evidence, and no participant recruitment is conducted under this project's agent-only assessment scope.
