# Reported interface acceptance for v0.2.3

Reviewed 7 October 2026 against the owner's twelve screenshots and acceptance outcomes. The before capture is the published v0.2.2 source `6ffb21015bfefa2fad87cae596056cd13fbf747e`. Synthetic draws are used for all retained result images. No account credential or clipboard contents are captured.

## Root cause and state inventory

The previous review emphasized startup, broad responsive geometry and animation lifecycle. It did not map each mode and reported outcome to its own acceptance probe. A grid gap was absent from the vocabulary column, icons used baseline placement, word-count exceptions reached a generic password error, and hover/focus state froze rotation independently from the Pause label. Fixed textarea height, intervening timer/help text and a progress track equal to the containing surface produced the other visible problems. Always-open settings and clear messages also required direct product review.

The correction uses one canonical checklist from `VINASIG/agent-standards`, not a new design system. Source `749503dd45ad99cac3d68ae2e79cfcc733d5293c` and bundle SHA-256 `e1b35145d8e69d87189248e8812c67d1aed1646ad0485027db16ca2f36e4dd54` were reviewed and installed with the official update CLI. Backup `2aad8eaa-0432-42e0-a176-29ad0ec5f20a` permits rollback. Managed-byte and root-budget checks pass; runtime discovery of a new agent session is a separate NOT_RUN observation. Both web profiles route to WEB-010 and the same `ui-contract.md`; core consumers receive no web helper.

Applicable states: password plus all three passphrase lists; Vietnamese/English; light/dark/system preference; initial/blocked JavaScript; ready/clear/error; typed and pasted malformed, empty, fractional, negative, lower/upper values; native arrow selection and forced colors; short results and 20 draws of each list's longest token; all three separators; masked/revealed state through generation/clear/reload; reduced motion and interrupted animation; running/midpoint/paused/resumed countdown with the pointer on Resume; copying/denial/pending completion; tab/lifecycle/inactivity cleanup. Widths include 320, 390, 759, 760, 761, 768, 1024 and 1440 px and 200 percent text. Existing browser tests retain the additional declared viewports. Cryptographic key generation is NOT_APPLICABLE: this app does not offer it.

## Execution and image review

Local `npm run verify` passes: strict types, lint, CSS syntax/declaration grammar, formatting, generated HTML, 25 unit/oracle tests, built license checks and dependency audit (zero findings). Exact v0.2.3 release identity and notes pass. The full browser run passes 108 cases across Chromium, Firefox and WebKit, with no retries, skips or unexpected outcomes; the raw JSON is retained at `output/ux-review/v0.2.3/browser-108.json`.

The first full run had 105 passes and three genuine failures in enlarged-text overflow, preserved at `output/ux-review/initial-ui-run-105-pass-3-overflow.json`. Fixed-width bit buttons caused one overflow; expanding the matrix to every mode also exposed the long English heading and metric labels at 320 px. Wrapping and shrinkable intrinsic text fix those causes; the page does not hide horizontal overflow. The final matrix checks every mode in both languages/themes at 320, 390, 768 and 1440 px with normal and 200 percent text. Other tests retain all additional declared viewports.

The initial Ubuntu CI run [37571945002](https://github.com/VINASIG/password-generator/actions/runs/37571945002) exposed a test timing error: 106 cases passed and two measured textarea height between a viewport change and its resize-observer rendering update. A separate rapid-resize probe reproduced the pre-paint mismatch in Chromium and WebKit and confirmed that the output fits after the next rendering cycle. The structural matrix now waits two animation frames after each viewport change, then asserts the same unclipped-output and layout invariants directly. It does not retry failed cases or relax the geometry thresholds. No production code changed for this correction.

Six fresh Lighthouse 13.5.0 runs (three mobile and three desktop) record a mobile performance median of 95, LCP 2,354 ms and TBT 81.5 ms; desktop median 100, LCP 485 ms and TBT 0 ms. All six have accessibility and best-practices scores of 100; CLS ranges from 0.00030 to 0.02575. SEO is 92 because Lighthouse's page-context robots fetch is denied by the intentional `connect-src 'none'`; the separate HTTP probe verifies valid robots bytes. These are local laboratory measurements on the recorded Windows host, not field metrics or participant evidence. [The machine-readable record](UI-VALIDATION-v0.2.3.json) binds the tested development HTML, source file digests and raw reports; exact release-commit CI and deployment checks remain separate. A fresh package directory passes Python's separate ZIP reader for the source, offline and 22-entry production site archives.
