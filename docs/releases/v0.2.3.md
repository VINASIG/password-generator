# v0.2.3

This research preview corrects the owner's reported interface defects and adopts the common VINASIG interface acceptance gate. Publication requires verification of this exact tagged revision, matching Ubuntu/Windows artifacts and build-origin attestations.

## Resulting behavior

- Choice cards use one visible selected surface with separated vocabulary options, vertically centered icons, native radio keyboard behavior and forced-colors focus/selection.
- Word-count, length, group and exclusion errors appear beside the affected field with linked accessibility descriptions. Both count controls use the same bounds.
- Desktop separator choices share one row. Target labels align with their bit buttons.
- Short results use a compact output; maximum-length phrases expand to fit. Hide, Copy and Clear sit 12 px below it. Eye/EyeOff icons follow the volatile visibility choice.
- Pause, Resume, selection and copying use one explicit state. Resume works with the pointer remaining on its button; hover alone does not freeze rotation. A pending clipboard write temporarily disables Resume.
- Countdown has a visible depleted track in both themes. Character options stay open, and the success message states that a new result was generated.
- Original shared header/footer artwork, theme action, CSS, fonts, vocabulary bytes and cryptographic sampling are preserved.

## Evidence

The [acceptance review](../UI-ACCEPTANCE-v0.2.3.md) maps every reported defect to a regression and opened synthetic images. The canonical standard adds WEB-010 for both web profiles, including deliberate negative fixtures; it is imported through a reviewed immutable bundle with a rollback record. Structural diagnostics, behavior tests and visual observations have separate scopes. This release does not claim independent review, participant usability evidence or that a checklist guarantees an interface without defects.
