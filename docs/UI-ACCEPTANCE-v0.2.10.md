# Release navigation validation follow-up

The configured animation and lifecycle implementation described in [the v0.2.9 review](UI-ACCEPTANCE-v0.2.9.md) is unchanged. Its local visual, browser and performance observations remain evidence for that implementation. v0.2.9 was not deployed: the separate main and tag CI runs revealed an intermittent wait in an existing no-JavaScript Firefox fixture.

The main Linux job and tag Windows job passed all 180 cases. The main Windows and tag Linux jobs each recorded 179 passes and one timeout in `page.goto`, before the no-JavaScript assertions executed. Both failed traces are retained under `output/motion-lifecycle-2026-10-07/publication/`. The trace shows a complete HTTP 200 document, a rendered page with disabled controls and the noscript explanation, while the navigation call waited for a `load` event until its unchanged 30-second limit. JavaScript was disabled, so neither the changed lifecycle nor the scramble code ran in that fixture. The trace identifies the unsatisfied driver wait, without proving its lower-level cause.

The fixture now separates HTTP navigation commitment from document readiness. It requires the exact route, HTTP 200 and `document.readyState === "complete"`, then performs the original locked-generation, visible explanation and hidden-output assertions. It additionally checks disabled Copy/Reveal/settings controls and an empty secret value. Browser automation reads document readiness; JavaScript remains disabled for the application throughout. The context is closed in a finally block. Assertions, test limits, retry policy, CSP, browser coverage and performance budgets are not relaxed.

The failed execution reports and traces remain preserved. One rerun request was made after diagnosing the first timeout; the same failure in the second OS job prompted this fixture correction, and that rerun was canceled. Publication requires fresh exact-revision Linux/Windows CI and artifact provenance. A passing later run does not replace the historical failures or establish third-party review or participant evidence.

Local follow-up records also preserve corrections to the added fieldset assertion. The generic disabled matcher does not describe a fieldset's own disabled state, and the property matcher failed in no-JavaScript Firefox. The final fixture checks the disabled HTML attribute and requires a nonempty set of child controls, each effectively disabled. It validates the intended gate through supported DOM behavior rather than dropping that check.

The final no-JavaScript fixture passed ten executions in each of Chromium, Firefox and WebKit (30 total) with no retries or skipped cases. The v0.2.10 local build, 27 unit/artifact tests, license review, locked dependency audit and final strict source/format checks passed. The configured animation and lifecycle runtime is byte-for-byte unchanged at source level from the reviewed v0.2.9 implementation; its existing 75-case affected run and 24-case capture remain applicable. Exact-revision release CI and deployed observations remain separate gates.
