# Configured animation and interrupted tab use

The owner reported that scramble frames used uppercase letters and digits regardless of the selected password groups or passphrase vocabulary, and that returning from another tab replaced an unexpired result. This review records the v0.2.9 correction. The previous interaction records remain historical descriptions of their named revisions.

## Causes and resulting behavior

The decorative alphabet was a fixed 32-character uppercase/digit string. Password frames now draw from the already-validated password plan after group selection, exclusions and ambiguity removal. Passphrase frames draw lowercase letters from the selected, integrity-verified vocabulary. The selected separator and internal underscores/hyphens remain at their final positions. Alphabet construction happens once per verified vocabulary, rather than scanning every word on each frame. Cosmetic draws use the existing bounded unbiased sampler separately from secret selection. They are not candidate passwords and are unavailable to Copy. The 1.2-second duration, 240 ms initial interval, progressive settlement, reduced-motion behavior and final output are retained.

The visibility handler previously cleared the result on hiding and called generation on every return. It now suspends the remaining countdown and removes the plaintext, scramble and temporary native-copy transfer from the DOM. The result stays only in volatile page memory. Returning restores that same result, remaining time, reveal choice and manual pause state. Returning during a scramble shows the completed result without starting another animation. A late clipboard callback cannot restore an old revision. Resize and motion callbacks cannot put hidden plaintext back into the DOM.

The 60-second interval measures visible time. For example, leaving with 45 seconds remaining and returning ten seconds later resumes from 45 seconds. The separate five-minute inactivity deadline includes hidden time and is checked before restoring, even if background timers were throttled. Expired and invalid results stay cleared. Actual page departure clears the session; a fresh page load, including one initially opened in the background, generates once after integrity verification. A settings edit while hidden invalidates the previous policy and defers the requested generation until return. There is no new secret storage or background network request.

Additional minimum-width inspection found WebKit kept a masked password on one overflowing line with `word-break: break-all`. Masked output now uses normal word breaking with the existing anywhere-wrap rule, while revealed password output retains its established wrapping. There is still one bullet per Unicode codepoint, and native/button Copy behavior is unchanged.

The original three reported regressions failed against the v0.2.8 artifact before implementation. Logs, trace archives, before/after synthetic screenshots and opened-image observations are retained under `output/motion-lifecycle-2026-10-07/`. Additional failure records are retained rather than overwritten: the first all-subsets WebKit fixture exceeded its unchanged 30-second test limit, so its full coverage was split across three five-subset cases; an older animation fixture assumed uppercase `A` instead of testing configured noise. Its replacement uses distinct lowercase final/noise values and retains the initial hold, progressive timing, final-secret and Copy assertions. The subsequent mask failure was reproduced before the focused wrapping correction.

Strict source/build checks, 27 unit/artifact/adversarial tests, license verification and the locked dependency audit passed locally. The final affected browser run passed 75 cases across Chromium, Firefox and WebKit, without retries or skipped cases. Full release CI, paired reproducibility, downloaded-asset provenance and deployed behavior are separate gates; this local review does not substitute for their actual execution.
