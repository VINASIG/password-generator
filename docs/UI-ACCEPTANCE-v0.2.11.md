# No-script navigation and publication validation

The configured animation and tab lifecycle implementation in [the v0.2.9 acceptance review](UI-ACCEPTANCE-v0.2.9.md) is unchanged. Its 75 affected browser cases, 24 synthetic visual captures and performance observations describe the same application source. Neither v0.2.9 nor v0.2.10 published a release or reached production. Their failed CI executions remain part of the evidence.

The [v0.2.10 follow-up](UI-ACCEPTANCE-v0.2.10.md) separated navigation commitment from document readiness. That local fixture passed 30 executions, but the subsequent Linux [main run](https://github.com/VINASIG/password-generator/actions/runs/37633686249) still timed out in Firefox's `goto` with `waitUntil: "commit"`. The Linux [tag run](https://github.com/VINASIG/password-generator/actions/runs/37633686915) encountered the same unresolved navigation wait in the shared preference oracle's initial no-script context. Both Windows jobs passed all 180 cases. Linux failures occurred before the affected no-script assertions, with 179 other cases passing in each job. Reports and traces are retained under `output/motion-lifecycle-2026-10-07/publication-v0.2.10/`.

No-script fixtures now use the existing document navigation primitive. It observes a main-frame HTTP 200 response, assigns the exact destination, and requires a new document at the exact URL with `document.readyState === "complete"`. A marker distinguishes the previous document even when the destination is the same. Response listeners are removed in a finally block. This verifies actual navigation and readiness without relying on the driver's unresolved `goto` promise. Application JavaScript remains disabled throughout these fixtures.

Normal application navigation still additionally waits for fonts and image decoding. That asynchronous visual preparation is kept separate from the no-script document checks. An initial attempt to share it with the no-script context encountered Firefox execution-context errors and is preserved under `output/motion-lifecycle-2026-10-07/noscript-navigation-first-failure/`. No-script tests did not previously assert font decoding; the correction preserves their HTTP, readiness, disabled-control and empty-secret assertions.

The pinned shared preference oracle is byte-for-byte unchanged. A local adapter changes navigation only for new pages inside its explicitly JavaScript-disabled context, rejects unsupported navigation options, and restores the browser context factory in a finally block. Script-enabled contexts continue to use their original browser methods. The oracle still checks its native locale links, disabled theme control, cookies, blocked storage and preservation of active work.

The corrected no-script generation fixture passed ten executions in each of Chromium, Firefox and WebKit, 30 total. The generation and shared preference cases together passed all six engine-specific cases. No retries, skips, test limits, assertions, browser coverage, CSP or performance budgets were relaxed. The final strict source and formatting check passed.

A [related upstream Firefox navigation report](https://github.com/microsoft/playwright/issues/42183) also describes unresolved driver navigation promises with load, DOMContentLoaded and commit waits. It uses a different application and does not establish that this project's failure has the same underlying cause. The project's own preserved traces and assertions provide the evidence for this narrowly scoped test-harness correction.

Publication still requires fresh exact-revision Linux and Windows CI, equal deterministic release bytes, exact-tag build provenance and deployed observations. Later successful runs do not erase historical failures or imply independent security review or participant evidence.
